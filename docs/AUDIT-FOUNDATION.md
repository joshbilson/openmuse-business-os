# Audit foundation (not deployed)

The optional `AuditWriter` and `scripts/oracle/audit-schema.sql` add a deliberately narrow,
redacted event format. Events contain an ordered sequence, UTC timestamp, owner or process ID,
action, source, outcome, optional request ID, previous hash, and SHA-256 event hash. They accept no
request URL, query string, body, provider response, transcript, financial value, or credential.
The admin-owned SQL function serializes concurrent appends under a row lock. An audit verifier can
check contiguous segments against an independently retained prior hash.

**Migration prerequisite:** Oracle currently creates the `openmuse` runtime role as database owner.
Before applying the migration, an administrator must transfer database ownership to
`openmuse_admin` and review all existing object privileges. Apply the SQL as `openmuse_admin` only.
It rejects a database still owned by `openmuse`; it grants that role function execution, not table
ownership or direct table mutation. The local PGlite test exercises function behavior and role
grants, but it is not a live Oracle privilege audit. The current request/action code does not yet
call `AuditWriter`, so no production application-access or event log is being generated by it.

This is an append-only **application boundary**, not immutable retention. An administrator with
control of Oracle can alter the database, code, clocks, and local log files. A hash chain detects
tampering only after its digest is anchored somewhere independent. To approach Xero's one-year
standard, add redacted access and action events to the live request path, export daily signed chain
heads and event segments to independently controlled retention for at least 400 days, preserve
Windows host/access events separately, and regularly verify chain continuity and recovery. Do not
claim Xero compliance until those steps are deployed and tested.
