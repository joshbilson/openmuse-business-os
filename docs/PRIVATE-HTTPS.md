# Private AES-256 HTTPS frontend

OpenMuse can listen on two local ports in the same API process: the existing HTTP API at `127.0.0.1:8791` for Hermes and MCP, and an optional HTTPS frontend at `127.0.0.1:8792`. The HTTPS listener accepts only TLS 1.2 `ECDHE-{RSA,ECDSA}-AES256-GCM-SHA384` and TLS 1.3 `TLS_AES_256_GCM_SHA384`. This deliberately excludes AES-128 and ChaCha20 clients. It has the same Hono routes, web assets, authentication and application state as the HTTP listener. It does not itself change Tailscale Serve.

This frontend addresses the observed AES-128 negotiation at the current Tailscale-terminated HTTPS endpoint. Xero's [API-consumer security standard](https://developer.xero.com/partner/security-standard-for-xero-api-consumers) says TLS 1.2 with AES-256 or higher and SHA-256 is mandatory. The selected AES-256-GCM suites use SHA-384; confirm Xero's interpretation of that wording if the attestation demands an exact SHA-256 suite. Encryption in transit is only one part of its standard; authentication, logging and monitoring still need separate evidence.

## Prepare without changing the public endpoint

1. In the existing protected `C:\OpenMuseBusinessOS\secrets` directory, obtain a certificate and key for the exact `oracle.<tailnet>.ts.net` hostname with `tailscale cert --cert-file=<protected-cert-path> --key-file=<protected-key-path> oracle.<tailnet>.ts.net`. Keep the private key out of the web root, repository, prompts and logs, and preserve the deployment's restricted Windows ACL. Tailscale documents the [file output and renewal responsibility](https://tailscale.com/docs/reference/tailscale-cli#cert). The files are separate from Revolut's client-authentication certificate.
2. Set `PRIVATE_HTTPS_CERT_FILE`, `PRIVATE_HTTPS_KEY_FILE`, and optionally `PRIVATE_HTTPS_PORT=8792` in the protected Oracle app `.env`. Leave `HOST=127.0.0.1`, `PORT=8791`, `PUBLIC_API_URL=https://oracle.<tailnet>.ts.net:10001`, `ALLOWED_ORIGINS`, all provider callbacks, and Hermes/MCP loopback URLs unchanged. Both certificate and key are required; a missing, expired, wrong-host or malformed certificate prevents API startup. Restart **only** the OpenMuse API task after reviewing the protected `.env` and taking the normal backup.
3. Before cutover, verify `http://127.0.0.1:8791/api/health` and `https://127.0.0.1:8792/api/health` locally. For the latter, use the public hostname as TLS SNI and HTTP Host, for example `curl --resolve oracle.<tailnet>.ts.net:8792:127.0.0.1 https://oracle.<tailnet>.ts.net:8792/api/health`. Verify `openssl s_client -connect 127.0.0.1:8792 -servername oracle.<tailnet>.ts.net -tls1_2` and `-tls1_3` each report an AES-256 suite; forced AES-128-only probes must fail. Check the actual certificate chain and hostname, not just the negotiated cipher.

## Cut over and roll back

Capture `tailscale serve status --json` first and preserve the current mapping for rollback. With the new local listener healthy, replace only the existing private port 10001 mapping: disable its `--https=10001` mapping, then set `tailscale serve --bg --tcp=10001 tcp://127.0.0.1:8792`. Use raw `--tcp`, **not** `--tls-terminated-tcp`, because Node must negotiate the TLS cipher. Tailscale [documents raw TCP forwarding](https://tailscale.com/docs/reference/tailscale-cli/serve#use-a-tcp-forwarder) and [`--bg` persistence](https://tailscale.com/docs/reference/tailscale-cli/serve#effects-of-rebooting-and-restarting). Keep Serve private; do not use Funnel. Tailnet access rules still apply. The browser, iPhone and provider OAuth redirects retain the same public URL and port.

From a separate tailnet device, check the public certificate, `api/health`, owner sign-in, web loading and one safe read-only connector status. Force both TLS versions and verify AES-256, then try AES-128-only offers and verify failure. If anything fails, restore the captured `--https=10001` mapping to `http://127.0.0.1:8791`; disabling the optional listener is a separate API restart and is not needed for immediate rollback. A local passing test is not evidence that the remote Tailscale mapping has been changed or validated.

Tailscale file certificates expire after 90 days and **do not renew automatically** in this mode. Monitor expiry well before day 90, request a renewed pair into protected staging paths (the CLI supports `--min-validity`), validate hostname/chain/key pairing, then stop only the OpenMuse API task, replace both files, and restart it. Recheck TLS 1.2/1.3 and HTTPS health; retain a protected rollback pair until the new listener is verified. Do not issue repeated certificates unnecessarily because [rate limits can delay issuance](https://tailscale.com/docs/how-to/set-up-https-certificates). The service loads files at startup and does not hot-reload them.

The local automated test generates a temporary self-signed certificate, serves a real HTTPS request, confirms the negotiated AES-256 suites for TLS 1.2 and 1.3, and confirms AES-128-only handshakes fail. It does not test Oracle's future certificate, Tailscale mapping, or iPhone/browser interoperability.
