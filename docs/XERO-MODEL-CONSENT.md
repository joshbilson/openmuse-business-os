# Xero data and model-provider consent: implementation boundary

This is an engineering design note, not an owner agreement or a claim of compliance. The current application **does not record separate consent to send Xero API data to a third-party model or live-audio provider**. Accepting the general workspace terms does not grant that consent.

The first fail-closed control withholds Xero facts from all six tools in the Hermes stdio business MCP bridge and the host-neutral `businessTools` adapter, including mixed-provider reads and source IDs used for generated views. The automatic business observer skips Xero sources before syncing or creating Hermes tasks. Authenticated owner-facing Xero status, sync, entities and views in the app's ordinary API remain available. This control does not authorize Xero-to-model use or establish user consent.

**This is a tool-output filter, not an enforceable security boundary against Hermes.** `scripts/oracle/configure.py` writes the owner `OPENMUSE_ACCESS_KEY` into both business and operator MCP environment entries in Hermes's `config.yaml`. The Hermes profile also has a local terminal and computer access. The live API and Hermes scheduled tasks currently run under the same Windows principal, so file permissions for that single principal cannot isolate the owner's key from Hermes. A model-invoked shell, another process with that key, or the operator bridge can authenticate directly to the owner API and read Xero endpoints without passing through the filtered business MCP tools. A future enforceable boundary needs a separate restricted credential and server-side authorization for model-origin requests, plus provenance checks across prompts and tool results. Keep the Xero/model path disabled operationally until those controls and the required consent are in place.

The proposed record is owner-scoped and versioned: the Xero tenant and connection generation, the specifically named model and live-audio providers, the stated purpose of sending Xero-derived data, the relevant privacy version, an explicit consent action, and a timestamp. A change of tenant, provider, purpose or privacy version requires a fresh choice. Revocation must block future disclosures; it cannot retract data already sent. Before enabling this path, confirm that each provider's handling of Xero API data fits the application's Xero agreement, including its restriction on AI training.

The following are distinct gates. A checkbox beside the Xero connection button would not cover them:

1. `apps/server/src/business/observer.ts`: Xero sources are now skipped entirely. A future consent gate must explicitly resume polling and define how to handle changes during the withheld period without silently losing them or flooding old history into new tasks. Already queued Xero tasks from before this control are not cancelled by the observer.
2. `apps/server/src/business/mcp-server.ts` and `apps/server/src/business/tools.ts`: Xero data is now withheld from these model-facing tools. Keep the fail-closed filtering when a future consent check is added; mixed-provider responses, view source IDs and unexpected response shapes must not bypass it. Other agent tools and previously saved text remain separate paths.
3. `apps/server/src/engine/model.ts` and `apps/server/src/conversations.ts`: task prompts, saved memory and previous chat messages can contain Xero results. Track provenance or conservatively withhold affected context before submission to Hermes's configured third-party model.
4. `apps/server/src/engagement/voice-provider.ts` and `apps/server/src/engagement/service.ts`: prior conversation context is sent to the live-audio provider, and delegated answers may contain Xero values. Obtain a separate explicit choice for this provider or keep Xero context and answers out of live voice.

The general owner acceptance gate records only the workspace terms and privacy versions. It does not unlock any of these model-disclosure paths. Test every gate both before consent and after revocation, including saved facts, mixed-provider queries, background tasks, prior conversations and an already connected Xero tenant. See [Xero's developer terms](https://developer.xero.com/xero-developer-platform-terms-conditions), especially clauses 7, 9 and 12, for the source requirements to review.
